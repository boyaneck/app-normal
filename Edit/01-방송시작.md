# 01. 방송 시작 → 모니터링 → 홈 목록

## 원래 문제

```
[방송 시작 버튼] → live_information 저장           ✅
                → 모니터링 페이지 이동               ❌ 없음
[OBS 송출 시작] → ingress_started 웹훅 → Redis 기록  ✅
                → "방송 중" 표시                     ❌ 아무도 안 함
[홈 메인 배너]  → Redis "LIVE_VIEWER_RANK" 조회      ❌ 웹훅은 "live:rank"에 저장
                → /live/live_list_now 라우트         ❌ 서버에 등록조차 안 되어 있음 (404)
[홈 목록]       → users.isLive = true 조회           ❌ 이 값을 바꾸는 코드가 없음
```

결과적으로 **방송을 시작해도 홈 어디에도 나오지 않았다.**

## 바뀐 구조

방송에 **상태(status)** 하나를 두고, "방송 중"인지는 **서버만** 판단한다.

```
ready ──방송 시작──▶ waiting ──OBS 연결──▶ live ──종료──▶ ending ──정리 완료──▶ ended
(브라우저가 바꿈)     (브라우저가 바꿈)     (서버만)        (서버만)            (서버만)
```

```
[설정 페이지]  ① 썸네일 → Supabase Storage 업로드 → URL만 DB에
               ② 제목/설명/썸네일 저장 + status = 'waiting'
               ③ /studio/live/{userId} 로 이동
[모니터링]     "OBS 연결을 기다리는 중" 오버레이 (3초마다 status 확인)
[OBS 시작]     LiveKit 웹훅 ingress_started
[Express]      status = 'live', started_at 기록, Redis INFO에 제목 저장
[홈]           status = 'live' 목록 (15초마다 갱신) / 메인 배너 Redis 키 수정
```

**왜 live는 서버만 바꾸나**: 버튼을 눌렀다고 실제로 방송이 나가는 건 아니다 (OBS를 켜야 함).
그리고 브라우저 값은 조작할 수 있다. LiveKit이 서명해서 보내는 웹훅이 가장 확실한 근거다.

### 함께 고친 통계 정확도 문제

`live-webhook.js`: **OBS(Ingress) 참가자와 호스트 모니터링 페이지(`HOST-*`)를 시청자에서 제외.**
예전에는 둘 다 `participant_joined`로 들어와 시청자 수·방문자 수가 실제보다 많게 기록됐다.

```js
// 변경 후
const isNotViewer = identity === roomName || identity?.startsWith("HOST-");
const viewer = identity && !isNotViewer ? identity : null;
```

## 썸네일을 Storage로 옮긴 이유

예전에는 Canvas로 압축한 이미지를 **base64 문자열 그대로 DB에 저장**했다.
홈 목록을 불러올 때마다 이미지 수십 장 분량의 글자를 받아야 했다.
이제 파일은 `thumbnails/{userId}/{timestamp}.jpg`에 올리고 DB에는 공개 URL만 저장한다.
(미리보기와 압축은 기존 `useImage` 그대로 사용, 업로드는 "방송 시작"을 누를 때 한 번만)
