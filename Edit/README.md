## 적용 순서 (꼭 이 순서로)

1. **DB 변경**: Supabase SQL Editor에서 `migration.sql` 실행
   - `live_stats.id`가 uuid면 SQL 안의 안내대로 `bigint` → `uuid`로 바꿔서 실행
2. **서버 환경변수** (`server/.env`, Render 환경변수에도 동일하게)
   - `SUPABASE_SERVICE_ROLE_KEY=` 추가 (Supabase > Project Settings > API의 service_role 키)
   - (선택) `COPILOT_DEMO=true`: 데모할 때만. 코파일럿이 빠르고 민감하게 반응함
   - (선택) `CLIENT_ORIGIN=배포된 프론트 주소`: 소켓 CORS
3. **프론트 환경변수**: `NEXT_PUBLIC_SERVER_URL`이 Express 서버 주소인지 확인 (이미 있음)
4. **Supabase 대시보드 > Database > Webhooks**: `live_stats` insert → `/live/live-analytics` 웹훅은 이제 꺼도 됨
   (켜둬도 중복 리포트는 생기지 않음)
5. 서버 재시작 → 프론트 재시작

## 동작 확인 체크리스트

- [ ] 방송 설정에서 제목/설명/썸네일 입력 → 방송 시작 → 모니터링 페이지로 이동, "OBS 연결 대기" 표시
- [ ] OBS 송출 시작 → 모니터링 배지가 LIVE로 바뀜 → 15초 안에 홈 목록에 방송이 뜸
- [ ] 모니터링 페이지 "방송 종료" → 통계 탭으로 이동 → 카드/차트에 방금 방송이 반영됨
- [ ] 통계 탭 AI 리포트 카드가 "분석 중" → 잠시 후 리포트 표시
- [ ] OBS만 직접 꺼도 모니터링 페이지가 통계 탭으로 자동 이동
- [ ] 채팅을 몰아서 치면 코파일럿 멘트가 뜨고, 👍/👎가 `copilot_insights.feedback`에 저장됨
- [ ] 음성 코파일럿에 "지금 시청자 몇 명이야?" → 실제 숫자로 답함

## 검증한 것 / 못 한 것

- ✅ 프론트 `tsc --noEmit` 통과, 변경 파일 ESLint 통과
- ✅ 서버 전체 모듈 import 확인, 감지기/판단 로직 시뮬레이션
  (평소 0~2개 채팅에는 침묵, 9개로 급증하면 1회 개입, 직후에는 쿨다운으로 차단)
- ❌ `next build`는 `.next` 폴더가 잠겨 있어 실행하지 못함 (dev 서버가 켜져 있는 것으로 보임)
- ❌ 실제 OBS/LiveKit/Supabase와 연결한 통합 테스트는 하지 못함 → 위 체크리스트로 확인 필요
- ❌ DB 스키마는 코드로만 추정함 (특히 `live_stats.id` 타입, `payments.host_id`)

## git 상태 참고

코파일럿 폴더 이동은 이력이 남도록 `git mv`로 했다. 그래서 이동/삭제된 파일은 이미 **stage된 상태**다.
커밋은 하지 않았다.
