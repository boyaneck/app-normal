# 03. 방송 통계의 AI와 채팅

## 1. AI 리포트가 사실상 항상 실패하고, 화면에도 안 나왔다

**원래**
- Supabase DB 웹훅(`live_stats` insert) → `/live/live-analytics` → Gemini 호출
- 프롬프트는 자유 텍스트를 요구하는데, 서버는 응답을 바로 `JSON.parse` → **거의 항상 파싱 실패**
- 성공해도 `ai_reports`에 어느 방송인지(id) 없이 저장
- 프론트에 `ai_reports`를 읽는 코드가 **없었다**

**변경**
- `server/src/prompt/AI-live-report-prompt.js`: 응답 형식을 JSON으로 명시
  ```json
  { "summary": "...", "good": [...], "improve": [...], "suggestions": [...] }
  ```
- `server/src/live/live-report.js` **(신규)** `generateLiveReport(statsRow)`
  - `finalizeLive`가 통계 저장 직후 **기다리지 않고** 호출 (종료 응답이 LLM 속도에 묶이지 않음)
  - 같은 방송에 리포트가 이미 있으면 아무것도 안 함 (멱등)
  - 비교 대상 "이전 방송"은 기준 방송의 `started_at`보다 이전 것 중 최신
  - `ai_reports.live_stats_id`에 연결해서 저장
- `server/src/live/live-analytics.js`: 기존 DB 웹훅 라우트는 같은 함수를 부르도록 축소 (켜져 있어도 중복 없음)
- `src/app/(browse)/studio/live-stat/ai-report.tsx` **(신규)** AI 리포트 카드
  - 리포트가 아직 없으면 "AI가 분석하고 있어요" → 5초마다 확인, 3분 후 확인 중단
  - 요약 / 잘 된 점 / 개선할 점 / 다음 방송 제안
- `live-stat.tsx`: 시청 지속률 옆(1/3)에 리포트 카드 배치

## 2. LLM이 두 개 (Gemini + Groq)

**변경**: `server/src/lib/llm.js` **(신규)** `chatCompletion({ messages, json, timeout })`
- 리포트, 통계 채팅, 코파일럿, 음성 코파일럿이 모두 이 함수 하나로 Groq를 호출
- `json: true`면 JSON 응답 모드 + 파싱 (앞뒤에 글자가 붙어도 `{...}`만 다시 파싱)
- 이제 `GOOGLE_AI_API_KEY`는 쓰지 않는다

## 3. 통계 AI 채팅이 카드 숫자 하나만 보고 답했다

**원래** (`POST /ai/chat`)
- 프론트가 계산한 `currentValue`, `prevValue`를 그대로 믿음 → 조작 가능
- "왜 떨어졌어?"에 답할 근거(시청자 추이, 다른 지표)가 없음
- 로그인 확인, 호출 제한 없음 → 누구나 내 Groq 키로 무제한 호출 가능

**변경** (`server/src/routes/ai-route.js`)
- 프론트는 `{ liveStatsId, cardKey, cardTitle, messages }`만 보냄
- 서버가 로그인한 호스트의 방송 기록을 **DB에서 직접** 읽음 (남의 방송 id면 거부)
- 프롬프트에 함께 넣는 것: 카드 값 + 이전 방송 대비, 방송 전체 지표, **시청자 추이 요약**(최대 12개 지점 + 최고점), AI 리포트 요약
- 로그인 필수(`requireUser`) + 사용자당 분당 20회 제한(`rateLimit`)
- 프론트: `src/api/AI.ts`에 `askStatChat()` 추가, `studio/page.tsx`가 axios 직접 호출 대신 사용
  `MiniCardInfo`에 `key`, `liveStatsId` 추가

## 4. 사용하지 않는 `/ai/analyze` 삭제

프론트 어디에서도 호출하지 않았다. 리포트는 1번의 자동 생성으로 대체.

## 5. TOP 후원자가 다른 스트리머 후원자까지 보여줬다 (개인정보)

**원래** `getTopSupporters()`: `payments` 테이블 **전체**를 가져와 브라우저에서 집계
→ 모든 스트리머의 후원자가 섞이고, 결제 데이터 전체가 브라우저로 내려감.
또 후원이 0건이면 **목업 후원자가 진짜처럼** 표시됨.

**변경**
- `src/api/live.ts`: `getTopSupporters(hostId)` → `.eq("host_id", hostId)`
- `top-supporters.tsx`: `hostId` prop 추가, 실제 데이터가 비어 있으면 "아직 후원 기록이 없어요"
  (목업은 hostId가 없을 때만)
- 남은 과제: 집계는 아직 브라우저에서 한다. 더 안전하게 하려면 Supabase RPC나 서버 API로 옮기고
  `payments`에 RLS(본인 것만 조회)를 켜야 한다 → `migration.sql` 5번 참고
