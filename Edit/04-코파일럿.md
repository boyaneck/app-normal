# 04. 코파일럿

## 구조 변경: 감지 → 판단 → 행동 → 전달

원래도 층이 나뉘어 있었지만 폴더 이름(`ema/`, `lib/`, `services/`)이 역할을 말해주지 않았다.
역할 이름으로 다시 나눴다. (이동은 `git mv`로 해서 파일 이력이 유지됨)

```
server/src/copilot/
  config.js                 (신규) 모든 설정값
  loop.js                   ← ema/loop.js      스케줄러 + 한 사이클(observe)
  sense/metric.js           ← ema/metric.js    Redis에서 채팅·후원·시청자 수
  sense/detector.js         ← ema/detector.js  EMA + z-score
  decide/decision.js        ← ema/decision.js  임계값·쿨다운·점수
  context/chat-context.js     (그대로)          채팅 닉네임·키워드·비율
  context/event-context.js  (신규)             후원·시청자 급증 맥락
  act/setup-intention.js    ← lib/...          무엇을 말할지 (규칙)
  act/generate-line.js      ← lib/...          LLM 한 문장
  act/history.js            (신규)             방별 직전 멘트
  deliver/insight-store.js  (신규)             멘트 기록 + 👍/👎 저장
```

**삭제**: `context/extract-context.js`, `context/copilot-prompt.js`, `services/interaction.js`
(어디서도 쓰지 않았고, 앞의 둘은 import에 `.js`가 빠져 있어서 불러오는 순간 서버가 죽는 상태였다)
`server/src/api/token.js`도 Next.js의 `src/api/token.ts`와 중복된 미사용 파일이라 삭제.

## A. 데모 설정이 그대로 남아 있었다 (가장 급했던 것)

**원래**: 주기 2초, z 임계값 0.3, 점수 0.1, 쿨다운 0, 워밍업 1
→ 채팅이 오는 동안 **거의 2초마다 LLM 호출**. 요청 한도에 걸리고 호스트는 알림 폭탄.
값이 4개 파일에 흩어져 있고 "두 파일 값을 같이 바꿀 것"이 주석으로만 존재.

**변경**: `copilot/config.js`

| 값 | 운영(기본) | 데모 (`COPILOT_DEMO=true`) |
|---|---|---|
| 관찰 주기 = 집계 윈도우 | 15초 | 3초 |
| 워밍업 | 5틱 | 1틱 |
| z 임계값 | 2.0 | 1.0 |
| 점수 임계값 | 0.8 | 0.3 |
| 쿨다운 | 45초 | 8초 |
| 표준편차 하한 | 1개 | 1개 |

관찰 주기와 집계 윈도우는 **같은 상수 하나**를 쓰므로 이제 어긋날 수 없다.

## B. z-score 계산 순서

**원래**: 현재 값으로 분산을 **먼저 갱신한 뒤** z 계산
→ 현재 값이 자기 기준선에 섞여서, 평평하다가 처음 튈 때 z가 크기와 상관없이 ≈ 2.18로 고정
(decision.js 주석에 직접 적어두었던 그 현상)

**변경** (`sense/detector.js`): **갱신 전 표준편차**로 z를 구한 뒤 기준선 갱신
```js
const z = delta / Math.max(prevStd, minStd);   // 1) 과거 기준으로 판단
ema = prevEma + alpha * delta;                  // 2) 그 다음 반영
ewvar = (1 - alpha) * (ewvar + alpha * delta * delta);
```
표준편차 하한을 `1e-6` → `1`(개수 단위)로 올려서, 평평할 때 채팅 1개에 z가 수십만이 되는 것도 막았다.
워밍업 판정은 `count >= warmUp` → `count > warmUp` (첫 틱은 비교할 과거가 없으므로)

**시뮬레이션 결과** (15초 단위 채팅 수 `1,0,2,1,1,0,1,2,1,9,12,2`)
- 0~2개 변동: 침묵
- 9개 급증: z=7.9 → 개입 1회
- 바로 다음 12개(z=2.3): 쿨다운으로 차단

## C. "할 말 없음"인데도 LLM 호출

**원래**: 어떤 규칙에도 안 걸리면 `intention: "nothing"` 기본 규칙 → 그래도 Groq 호출
**변경**: 기본 규칙 삭제 → 매칭 없으면 `null` → LLM 호출 안 함.
`decision.js`도 값이 0인 지표는 후보에서 제외.

## D. "직전 멘트와 겹치면 출력하지 마라"인데 직전 멘트를 안 줬다

**변경**
- `act/history.js`: 방마다 최근 멘트 3개 기억 (방송 종료 시 초기화)
- `act/generate-line.js`: 프롬프트에 `[직전 멘트]` 섹션 추가
- 말할 필요가 없으면 모델이 `SKIP`만 출력하도록 약속 → 그 경우 호스트에게 보내지 않음

## E. 음성 코파일럿(`POST /ai/copilot`)이 항상 500 에러

**원래 버그**
1. 정의되지 않은 `context` 변수 사용 → 매번 ReferenceError
2. `redis_client` import 누락
3. 후원 정규식 끝의 `|` → 빈 문자열과 매칭되어 **모든 질문이 후원 질문**
4. `VIEWERS`, `PEAK_VIEW`는 Hash인데 `get`으로 읽음
5. `hostId`를 body로 받음 → 남의 방송 데이터를 물어볼 수 있음
6. 프론트가 `http://localhost:3001` 하드코딩

**변경**
- 방송 스냅샷(경과 시간, 현재/최고 시청자, 채팅 참여자, 후원, 시청자 추이, 최근 채팅 15개)이 작아서
  키워드 분기 없이 **항상 통째로** 전달. 자료형에 맞게 `hLen`, `hGet` 사용
- 최근 채팅은 `<viewer_chat>`으로 감싸 프롬프트 인젝션 방어
- 방은 로그인 토큰으로 결정, 로그인 필수 + 분당 10회 제한
- 프론트 `askAICopilot(question)` (hostId 제거), 실패 시 안내 문구 표시

## F. 서버가 재시작되면 코파일럿이 멈췄다

**원래**: 루프와 EMA 상태가 메모리(`setInterval`, `Map`)에만 있고, 루프는 `ingress_started` 때만 시작
→ 방송 도중 Render 재배포/슬립이 일어나면 그 방송은 끝까지 코파일럿 없음

**변경** (`server/src/app.js`): 서버가 켜질 때 `status = 'live'`인 방의 코파일럿·시계열 루프를 다시 시작.
(EMA 기준선은 새로 쌓이므로 워밍업 시간만큼은 조용하다)

## G. 채팅만 감지했다

**원래**: 후원·시청자도 감지는 했지만 의도 규칙이 없어서 `decision.js`에서 일부러 꺼둠
**변경**
- `context/event-context.js`: 최근 1분 후원자 닉네임·금액 / 현재 시청자 수
- `act/setup-intention.js`: 후원 급증 → 후원자 이름 불러 감사 인사, 시청자 급증 → 새 시청자 인사 + 방송 소개
- `decide/decision.js`: 세 지표 모두 후보, 가중치(후원 1.0 / 채팅 0.8 / 시청자 0.6)는 `config.js`로 이동
- 후원자 닉네임도 사용자 입력이라 `<viewer_chat>`으로 감쌈

## H. 피드백 루프 (👍/👎)

코드에 "나중에 ✅/❌ 달 데이터"라고 적혀 있던 부분을 구현했다.

```
loop.js 멘트 생성 → copilot_insights 저장 (metric, z, score, value, intention, line)
                  → 호스트에게 { id, line } 전송
AI-answer.tsx 👍/👎 → 소켓 "copilot-feedback" { insightId, feedback }
copilot-socket.js → feedback 저장 (room_name 조건으로 남의 기록은 수정 불가)
```

데이터가 쌓이면 "z가 몇일 때 👍가 많았나"를 보고 `config.js` 임계값을 조정할 수 있다.
기록 저장이 실패해도 멘트 전달은 그대로 되고, 그 멘트에만 피드백 버튼이 안 뜬다.

## 보안: 코파일럿 소켓이 남의 방에 붙을 수 있었다

들어갈 방은 브라우저가 보낸 `query.hostId`를 그대로 사용 → A 방 호스트가 B 방 코파일럿을 엿볼 수 있었다.
**변경**: 방 이름은 **서명 검증된 LiveKit 토큰 안의 `room`**으로만 결정. `hostId`가 다르면 거부.
`canPublish` 권한도 함께 확인.
