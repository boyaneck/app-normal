# 05. 보안 · 환경설정

## 1. Express 서버에 로그인 검증 추가

**원래**: Express 라우트는 누가 요청했는지 확인하지 않고 body의 `userId`/`hostId`를 그대로 믿었다.
개발자도구로 값만 바꾸면 남의 방송을 끄거나, 남의 데이터를 물어보거나, 내 LLM 키를 무제한으로 쓸 수 있었다.

**변경**
- `server/src/middlewares/require-user.js` **(신규)**:
  `Authorization: Bearer <Supabase access token>`을 `supabase.auth.getUser(token)`으로 검증 → `req.user`
- `src/lib/server-api.ts` **(신규)**: `getAuthHeaders()`가 로그인 세션의 access token으로 헤더 생성
- 적용: `POST /live/end`, `POST /ai/chat`, `POST /ai/copilot`
- 원칙: **"누가"는 항상 서버가 토큰으로 정한다.** body로는 "무엇을"만 받는다.

## 2. AI 호출 횟수 제한

`server/src/middlewares/rate-limit.js` **(신규)**: Redis 기반 사용자별 고정 윈도우 제한
- `/ai/chat` 분당 20회, `/ai/copilot` 분당 10회
- Redis 장애 시에는 통과 (서비스가 멈추지 않도록)

## 3. 서버의 Supabase 키

`server/src/config/supabase.js`: `SUPABASE_SERVICE_ROLE_KEY`가 있으면 우선 사용, 없으면 기존 anon 키.
- 서버는 웹훅으로 방송 상태·통계·리포트·코파일럿 기록을 쓴다. RLS를 켜면 anon 키로는 쓸 수 없다.
- ⚠️ service role 키는 RLS를 우회하므로 **서버 .env에만** 둔다. `NEXT_PUBLIC_`을 붙이면 브라우저로 나간다.

## 4. 하드코딩된 localhost 제거

`src/lib/server-api.ts`의 `SERVER_URL`(`NEXT_PUBLIC_SERVER_URL`)로 통일.

| 파일 | 예전 |
|---|---|
| `src/api/live.ts` (추천, 홈 트렌딩, 메인 배너) | `http://localhost:3001/...` |
| `src/api/AI.ts` | `http://localhost:3001/ai/copilot` |
| `studio/live/[id]/page.tsx` 코파일럿 소켓 | `http://localhost:3001/copilot` |

## 5. 프론트 Supabase 쓰기에 로그인 세션 사용

방송 설정 저장과 썸네일 업로드는 `createClientComponentClient()`(로그인 쿠키가 실린 클라이언트)를 쓴다.
기존 `supabaseForClient`는 세션 없는 anon 클라이언트라서, RLS를 켜면 "본인 row만 수정" 같은 정책을 적용할 수 없었다.

## 환경변수 정리

### 서버 (`server/.env`, Render)
| 변수 | 상태 | 용도 |
|---|---|---|
| `SUPABASE_SERVICE_ROLE_KEY` | **추가 필요** | 서버 쓰기 (RLS 우회) |
| `COPILOT_DEMO` | 선택 | `true`면 코파일럿 데모값 |
| `CLIENT_ORIGIN` | 선택 | 소켓 CORS 허용 주소 (기본 localhost:3000) |
| `LIVEKIT_URL` | 기존 | 이제 방 삭제(`/live/end`)에도 사용 |
| `GOOGLE_AI_API_KEY` | 더 이상 안 씀 | 리포트도 Groq로 통일 |

### 프론트 (`.env.local`, Vercel 등)
| 변수 | 상태 |
|---|---|
| `NEXT_PUBLIC_SERVER_URL` | 기존. Express 주소인지 확인 |

## ⚠️ 이번에 고치지 않은 보안 이슈 (확인 필요)

- `.env.local`에 **`NEXT_PUBLIC_IAM_PORT_SECRET_KEY`**가 있다.
  `NEXT_PUBLIC_`이 붙은 값은 브라우저 JS에 그대로 포함되어 누구나 볼 수 있다.
  지금 코드에서는 쓰지 않는 것으로 보이지만, **이미 배포된 적이 있다면 키를 재발급(rotate)하고 변수를 삭제**하는 것을 권장한다.
- `payments`, `live_information` 등의 RLS가 꺼져 있다면, anon 키로 브라우저에서 다른 사람의 데이터를 읽고 쓸 수 있다.
  `migration.sql` 5번의 정책을 동작 확인 후 켜는 것을 권장한다.
- 소켓 채팅(`send_msg`)은 보낸 사람의 `id`를 브라우저 값 그대로 쓴다 (이번 범위 밖).
