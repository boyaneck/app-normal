# 02. 방송 종료 → 통계 페이지

## 원래 문제

- 모니터링 페이지에 **종료 버튼이 없었다.** (설정 페이지의 버튼은 화면 토글만 했음)
- 통계 계산이 `room_finished` 웹훅 안에 100줄 넘게 들어 있어서, 다른 곳에서 재사용할 수 없었다.
- `ingress_ended`(OBS 종료)에서는 루프만 멈추고 통계는 `room_finished`를 기다렸다.
  `room_finished`는 "방이 비었을 때" 오는 이벤트라, 시청자나 모니터링 페이지가 남아 있으면 늦게 오거나 안 올 수 있다.
  (실제 동작은 환경마다 다를 수 있어 서버 로그로 확인 권장 — 아래 설계는 어느 쪽이든 안전하게 동작함)
- 통계를 저장해도 **방금 저장한 row의 id를 알 수 없어서** 통계 페이지/AI 리포트와 연결할 수 없었다.

## 바뀐 구조: 종료 경로를 하나로

```
[웹 "방송 종료" 버튼] ─▶ POST /live/end (로그인 토큰) ─┐
[OBS 송출 끔]        ─▶ 웹훅 ingress_ended            ─┼─▶ finalizeLive(roomName)
[방이 비어서 닫힘]    ─▶ 웹훅 room_finished (안전망)    ─┘
                                                          │
         ┌────────────────────────────────────────────────┘
         ▼
  Redis 잠금 SET NX (60초)  ← 셋 중 무엇이 먼저 와도 한 번만 실행
  코파일럿·시계열 루프 중지
  started_at 없음? → status = ready 로 되돌리고 끝 (OBS 연결 전에 종료한 경우)
  status = ending
  Redis → 통계 계산 → live_stats 저장 (id 포함 row 반환)
  Redis 정리 (채팅 히스토리 포함)
  status = ended
  AI 리포트 생성 시작 (기다리지 않음)
         │
         ▼
[종료 버튼 응답] { result, liveStatsId }
[브라우저] /studio?tab=liveStat 으로 이동 → 최신 방송 카드·차트 + AI 리포트
```

**`/live/end`는 어떤 방송을 끌지 body가 아니라 로그인 토큰의 user id로 정한다.**
body로 받으면 남의 방송도 끌 수 있다.

종료 버튼은 서버에서 LiveKit 방을 삭제(`deleteRoom`)해서 시청자와 OBS 참가자를 내보낸다.
⚠️ OBS의 "자동 재연결" 설정이 켜져 있으면 다시 붙을 수 있다. 그래서 확인창에서 "OBS 송출도 꺼주세요"라고 안내한다.
(Ingress를 삭제하면 스트림 키가 바뀌어 매번 OBS 설정을 다시 해야 해서, 삭제하지 않는 쪽을 택했다)

## 파일별 변경

### 서버

| 파일 | 변경 |
|---|---|
| `server/src/live/finalize-live.js` **(신규)** | 종료 처리 전체. 잠금, 상태 변경, 통계 계산(`collectLiveStats`), 저장, Redis 정리, 리포트 시작. 저장 실패 시 잠금을 풀어서 재시도 가능 |
| `server/src/live/end-live.js` **(신규)** | `POST /live/end` 컨트롤러. finalize → 방 삭제 → `liveStatsId` 응답. 웹훅이 먼저 정리했으면(skipped) 최신 통계 id 반환 |
| `server/src/live/timeseries.js` **(신규)** | 5분 주기 시청자 시계열 기록을 webhook에서 분리 (finalize, 서버 재시작 복구에서 재사용) |
| `server/src/live/live-webhook.js` | `ingress_ended`, `room_finished` → 둘 다 `finalizeLive()` 호출. 기존 계산 로직과 시계열 함수 제거 |
| `server/src/api/live.js` | `insertLiveStats()`가 true/false 대신 **저장된 row(id 포함)**를 반환. `getLatestLiveStats`, `getLiveStatsById` 추가. `getPrevLive`가 "최신순 2번째" 대신 "기준 방송보다 이전 것 중 최신"으로 조회 |
| `server/src/routes/live-route.js` | `POST /live/end` (requireUser) 등록 |

## 통계 화면 연결

카드·차트는 원래도 `live_stats`를 보고 있었다. 종료 시 그 테이블에 새 row가 생기므로 별도 매핑 변경 없이 바로 반영된다.
추가로 각 row의 `id`를 화면 데이터에 포함시켜서 AI 리포트와 AI 채팅이 "어느 방송"인지 알 수 있게 했다.

| 화면 | 데이터 |
|---|---|
| 평균/최고 시청자, 총 방문자, 후원, 채팅 전환율 카드 | `live_stats` 각 컬럼 |
| 주간 차트 | `live_stats` 최근 7개 |
| 시청 지속률 | `live_stats.retention_rate` |
| TOP 후원자 | `payments` (호스트 기준, 03 문서 참고) |
| AI 리포트 (신규 카드) | `ai_reports.live_stats_id` |

`src/api/live.ts`의 `getWeekleyPost()`는 다른 테이블(`post_live_stats`)을 보던 미사용 함수라 삭제했다.

## 함께 바뀐 동작

- 방송 종료 시 Redis 채팅 히스토리(`live:{room}:msg`)도 지운다.
  남겨두면 다음 방송 코파일럿이 지난 방송 채팅을 분석했다.
  (대신 종료 직후 재입장한 시청자에게 지난 채팅이 복구되지 않는다)
